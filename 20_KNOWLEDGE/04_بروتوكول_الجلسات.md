# 🔁 بروتوكول الجلسات — كيف تسير كل محادثة (ملزم)

## دورة العمل: ملف واحد لكل جلسة
```
① البداية    محمد يقول: «نشتغل على <اسم الملف>» (+ يلصق تقرير 🩺/🐞 إن وُجد)
② الفهم      كلود يقرأ: 00_طريقة_العمل ← بنود الملف من GMT_MASTER_v3 ← 03_طلبات_المالك ← ثم الكود الفعلي بعمق
③ الأسئلة    إن وُجد غموض: رسالة واحدة، أسئلة مرقّمة، مع رأي مقترح لكل سؤال — ثم انتظار الجواب
④ التنفيذ    إصلاح البنود بالسبب الجذري (رقم السطر) — لا لمس لملف آخر إلا بإذن صريح
⑤ التسليم    الملف المعدَّل + قائمة «ماذا تختبر» خطوة بخطوة + ما تغيّر بالضبط
⑥ التحقق     محمد يجرّب على المنشور ويرسل النتيجة (نجح/تقرير أخطاء) — نكرّر ④⑤ حتى يقول «تمام»
⑦ الختام     ⭐ عند اعتماد الملف، كلود يسلّم «حزمة نهاية الجلسة»:
             ملف مضغوط فيه المشروع كاملاً بعد التعديلات + التوثيق محدَّثاً:
             - 01_سجل_التحديثات (ما أُنجز بهذه الجلسة + حالة الجولات)
             - GMT_MASTER_v3 (البنود المُغلقة تُعلَّم ✅ مع تاريخها)
             - 03_طلبات_المالك (أي طلب/قرار جديد يُضاف)
             هذه الحزمة هي مدخل الجلسة التالية — فلا يضيع شيء أبداً.
```

## قواعد لا تُكسر
1. **ملف واحد.** لو احتاج الإصلاح ملفاً ثانياً (مثلاً SQL أو ملف مشترك) ⇒ يُقال صراحة ويُستأذن.
2. **السبب قبل الحل.** كل إصلاح يُشرح: أين الخطأ (سطر) · لماذا يحدث · كيف يُصلَح — لا ترقيع أعمى.
3. **لا حذف بيانات** — الحذف ناعم دائماً، والعمولات تُصفَّر لا تُحذف.
4. **تصحيح الافتراضات بالدليل** — إذا قال محمد شيئاً والكود يقول غيره، يُقال له بالدليل.
5. **الملفات المشتركة**: أي تعديل عليها ⇒ التنبيه أنه يجب نسخه لكل المجلدات بالمستودع، ورفع إصدار `sw.js` بالمجلدات الخمسة (02–06) عند أي تعديل داخلها.
6. **اللوجو:** صورة المالك كما هي، بأماكن اللوجو والأيقونات فقط. لا توليد شعارات إطلاقاً.
7. **الترقيم ثابت** (PUR-1, INV-2…) — يُستعمل بكل مراسلة.
8. **العربية** لغة العمل والتقارير والتعليقات.
